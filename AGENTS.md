# Правила проекта TorrentTV (ВНосКино, Android TV)

## Публикация релиза — ОБЯЗАТЕЛЬНАЯ часть работы

«Закоммитить» в этом проекте всегда означает полный цикл, без напоминаний пользователя:

1. Поднять `versionCode` (+1) и `versionName` в `app/build.gradle.kts`.
2. Закоммитить: сообщение в формате `vX.Y.Z: краткий список изменений по-русски`.
3. Запушить `main` **и в ветку `release`**: `git push origin main main:release`.
4. Релиз собирает **только CI** (`.github/workflows/release.yml`): он подписывает APK
   секретом `KEYSTORE_B64` и сам публикует GitHub Release с ассетом `VNosKino-X.Y.Z.apk`.
   Проверить: `gh run list --workflow=release.yml` → `gh release view vX.Y.Z`.

### ⛔ ЗАПРЕЩЕНО: ручной релиз с локальной сборкой

- Локальный `assembleRelease` подписывается **debug-ключом** (секреты подписи есть только
  в CI) — такой APK не устанавливается на ТВ: «пакет конфликтует с существующим пакетом»
  (подпись не совпадает с установленным приложением).
- Никогда не делать `gh release create` вручную и не пушить теги релизов вручную —
  релиз и тег создаёт CI на пуше в `release`. Приложение обновляется по воздуху
  с GitHub Releases и проверяет подпись.
- Если такой релиз всё же создан: `gh release delete vX.Y.Z --yes` +
  `git push origin :refs/tags/vX.Y.Z` + удалить локальный тег, затем пуш в `release`.

Правки только документов (`AGENTS.md`, `README.md`) можно пушить в `main` без релиза —
без bump версии и без пула в `release`.

## Проверка логов с ТВ

- `gh gist list` — логи устройства приходят как Gist «ВНосКино лог <дата>» (автовыгрузка
  при ошибке плеера, ручная — из настроек). Читать: `gh gist view <id> -f vnoskino_log.txt`.
- Приложение пишет события с префиксами: `[player]`, `[search]`, `[smart]`, `[netcheck]`,
  `[update]`, `[upload]`, `[app]`. Хвост файлового лога и последний краш — в конце Gist.
- ТВ работает не с локальным кодом, а с последним релизом: новые правки на устройстве
  не проверяются, пока не опубликован релиз.

## Конвенции кода

- Комментарии и строки UI — по-русски; причина изменения — в комментарии, а не только в diff.
- Запросы к базам фильмов (КП/TMDB) — только через общий кеш `KinopoiskClient.shared*`
  (свежий кеш без сети, фолбэк на устаревший кеш при сбое источника).
- Сетевые вызовы — в `Dispatchers.IO`, ответы кешируются (лимиты API не расходовать).
- `delay`/suspend — только в корутинах; внутри колбэков ExoPlayer — `CoroutineScope(...).launch`.
- `requestFocus()` на Compose `FocusRequester` — всегда в `runCatching` (ТВ-фокус бывает не готов).
- Временные/тестовые блоки UI помечать `🧪 ТЕСТ (временно)` и убирать в следующем релизе.

## Тексты UI и логи — кратко, для пользователя

- UI-тексты — короткие (одна строка), без инструкций «для разработчика»
  (gradle.properties, ключи, регистрация) — это не для экрана ТВ.
- Не писать в лог приложения URL выгрузок (`[upload] sent -> …`) — он виден
  пользователю на экране логов и копится в следующих выгрузках. Достаточно
  «выгрузка ок» / «выгрузка FAIL»; URL разработчик получает через `gh gist list`.

## Память агента — записывать автоматически

Важное фиксируется в памяти (codegraph `remember_session`) сразу, без просьбы пользователя:

- причина найденного бага и решение;
- архитектурные решения и договорённости с пользователем;
- устройство инфраструктуры: где что лежит, как собирается и публикуется;
- уроки ошибок (что нельзя делать и почему);
- итог значимой задачи: что сделано, что осталось.

Перед новой задачей по знакомой теме — сначала `search_notes`. Заметки короткие,
фактические, с путями и командами, чтобы по ним можно было действовать без контекста.

## Окружение

- macOS, shell zsh; Gradle wrapper: `./gradlew`.
- Ключи API (КП, TMDB) вшиты через gradle-свойства/CI-секреты — в репозиторий не класть.
- Сессии `ses_*.json`, keystore и пароли — в `.gitignore`, не трогать и не коммитить.
